<Update label="June 3, 2026" description="Multiple notification channels with native Slack, Discord, and Google Chat delivery" tags={["UI", "Install"]}>
  - **Notifications now fan out to multiple channels.** Settings → Notifications manages a list of channels — each with its own URL, format, priority floor, optional ntfy token, and enabled/disabled toggle. A workflow report is delivered to every enabled channel independently. Pre-existing single-webhook configs continue to work as a synthesized "Default" channel.
  - **Native Slack, Discord, and Google Chat delivery.** Breadbox auto-detects the target platform from the webhook URL and sends in the platform's native wire format: Slack incoming webhooks receive mrkdwn with a bold title, priority emoji, and "View report →" link; Discord webhooks receive markdown capped at 2 000 characters with an auto-linked deep-link; Google Chat webhooks receive `{"text": …}` with unicode emoji. `notify.format` now accepts `slack`, `discord`, and `googlechat` in addition to `ntfy`, `json`, and `auto`.
  - **Minimum priority floor.** Each channel has its own priority floor (`info` | `warning` | `critical`). Reports below the floor are dropped for that channel; test sends always go through.
  - **Retries with backoff.** Each delivery retries up to 3× on network errors, 429, or 5xx responses with exponential backoff. 4xx errors (other than 429) fail fast without retrying.
  - **ntfy token and action button.** A per-channel ntfy token authenticates via `Authorization: Bearer` for protected or self-hosted ntfy topics. Each ntfy delivery includes a "View report" action button (`X-Actions`) alongside the click-through deep link.
  - **Per-channel delivery status.** Each channel row shows the last delivery attempt — timestamp, resolved format, and success or error detail.
  - **"Test all" fires a test delivery to every enabled channel at once** from the Channels section header.
  - **Deep-link origin is auto-detected.** Breadbox captures the admin's browser origin on each visit to Settings → Notifications, so notification deep links resolve correctly without setting `notify.public_base_url` manually. The manual override still takes precedence when set.
  {/* closes #1699 */}
</Update>

<Update label="June 3, 2026" description="Developer Mode: opt-in bug and task reporter" tags={["UI"]}>
  - **Developer Mode adds a floating bug and task reporter to every admin page.** Enable it under **Settings → Developer** with a single toggle — no GitHub token required to get started.
  - **Filing captures a screenshot and HTML snapshot of the current page**, then opens a prefilled GitHub issue draft in your browser (no token) or files a labelled issue directly via the API (with a personal access token). Breadbox defaults to filing against `canalesb93/breadbox`; the target repo is overridable in settings.
  - **Financial data is redacted before anything leaves your instance.** Amounts, names, merchants, and emails are masked in both the screenshot and the HTML snapshot by default. The live page is never mutated — redaction runs on a detached clone.
  - **Reports are stored as a durable in-app audit trail.** Filed issues and draft URLs are linked back to the captured artifacts, visible from the Developer settings tab.
  {/* closes #1701 */}
</Update>

<Update label="June 3, 2026" description="Feed reports as individual cards, Rule Foundation option clarified, drawer scrim fix" tags={["UI"]}>
  - **Every workflow report in the activity feed now appears as its own comment-bubble card**, with an unread "New" badge when unseen. Reports no longer fold into the parent session or bulk-action card they came from.
  - **Rule Foundation's "Draft only" option is replaced by "Create rules only — skip backfill".** Both options in the configure drawer now create the vetted rules (so future syncs auto-categorize); they differ only in whether to retroactively backfill existing transactions. The standalone propose-without-creating mode is removed.
  - **Side-drawer scrims now correctly dim the sidebar.** The scrim previously tied the sidebar's z-index and left it lit while the content area dimmed; it now sits above the navigation rail so the full page is covered.
  {/* closes #1704, #1705, #1706 */}
</Update>

<Update label="June 2, 2026" description="Getting Started redesigned as a guided onboarding journey" tags={["UI"]}>
  - **Getting Started is now a step-by-step onboarding surface.** The flat 5-card checklist is replaced by a circular progress ring that warms up as you advance, hierarchical step rows (the next actionable step is elevated, completed steps collapse to quiet confirmations, pending steps are muted), and a live spinner during the first sync.
  - **Per-step inline stats** appear once a step produces data — connection count, transaction count, member count, and API-key count — so the dashboard's state is visible without navigating away.
  - **"What's next" destination grid** appears once every step is complete, surfacing suggested follow-up actions (review transactions, create a rule, set up a workflow, invite a household member). The stats strip is now always visible, even before the first transaction syncs.
  {/* closes #1691, #1692 */}
</Update>

<Update label="June 2, 2026" description="Curated workflow gallery, per-workflow names, and one-off run polish" tags={["UI"]}>
  - **Gallery curated.** Three presets removed (Subscription Auditor, New-Merchant Watch, Duplicate Charge Detector). A new **Setup & Bulk** section at the top adds two on-demand one-off workflows: **Rule Foundation** (analyzes your last 1000+ transactions and drafts auto-categorization rules with a dry-run preview before applying) and **Bulk Catch-Up** (categorizes your entire pending backlog in one pass, leaving only ambiguous charges flagged for manual review).
  - **On-demand workflows run from a button.** One-off workflow cards show a **Run** button in place of a schedule toggle. The button displays a live spinner while the run is in progress and shows a toast with a direct link to the run once it completes or fails.
  - **Rename and re-avatar any workflow.** Open the configure drawer to edit a workflow's display name and shuffle its DiceBear avatar.
  - The provider connections directory now separates **Connections** (Plaid, Teller) from **Manual import** (CSV); the Test connection button moves to the drawer footer.
  - The Grouped/List view toggle on `/transactions` now renders as a proper connected segmented control.
  {/* closes #1684, #1689, #1690, #1693, #1694 */}
</Update>

<Update label="June 2, 2026" description="Dedicated notifications settings page and ntfy-native delivery" tags={["UI", "Install"]}>
  - **Notifications has its own settings page.** Configure the webhook URL, delivery format, and public base URL under **Settings → Notifications**, decoupled from the Workflows tab.
  - **Native ntfy delivery.** When the webhook URL resolves to an ntfy server, Breadbox sends in ntfy's native format: a title, priority level (info → 3 / warning → 4 / critical → 5), Markdown body, a per-priority emoji tag, and an `X-Click` deep-link back to the relevant page.
  - **Two new config keys:** `notify.format` (`auto` | `ntfy` | `json`; `auto` sniffs the URL) and `notify.public_base_url` (absolute origin used to make deep-links and relative body links work on an external ntfy server). The generic JSON delivery path is unchanged for Slack-compatible relays and Discord bridges.
  {/* closes #1687 */}
</Update>

<Update label="June 1, 2026" description="Topbar breadcrumb, provider drawers, and schedule timezone fix" tags={["UI"]}>

<Update label="May 31, 2026" description="Agents → Workflows: redesigned gallery, configurable drawer, and list_workflows MCP tool" tags={["UI", "MCP"]}>
  - **Agents is now Workflows.** `/agents` and `/agents/definitions` redirect permanently to `/workflows` and `/workflows/runs`; `/settings/agents` redirects to `/settings/workflows`. API paths and preset slugs are unchanged.
  - **Redesigned gallery.** The Workflows list shows Mintlify-style rows with per-workflow status tiles. Clicking a row opens a slide-over configure drawer — no full-page navigation required.
  - **Configure each workflow independently.** The drawer lets you set the model, trigger type (`sync`, `schedule`, or `manual`), cron schedule with a live next-five-runs preview, and a per-run cost cap.
  - **Run detail shows which model was used.** Every completed run now records and surfaces the model that executed it.
  - **Actionable error messages on failed runs.** The run detail page shows a plain-English reason instead of a raw exit-code string.
  - **Settings entry moved into the sidebar System section.** The Settings rail now extends as a true sidebar panel.
  - **`list_workflows` MCP tool.** Returns your household's enabled workflows (name, slug, trigger, cron schedule, last-run status) and the full preset catalog available to enable. Enabling or configuring workflows is an admin-UI action; the tool is read-only.
  - Workflow run transcript links to reports now resolve correctly.
  - Recurring and Workflows are now searchable in the command palette. You can also switch the colour theme directly from the palette, and the theme toggle in the top bar is now always visible.

<Update label="May 31, 2026" description="Recurring: type field, series editing, and Subscriptions rename" tags={["UI", "API", "MCP"]}>
  - **Subscriptions is now Recurring.** The section covers every kind of repeating charge — subscription, bill, loan, or other — not just subscriptions. The URL changed from `/subscriptions` to `/recurring`; existing links redirect.
  - **Series type field.** Each series carries one of four types — `subscription`, `bill`, `loan`, `other` — inferred automatically from linked charges' categories and overridable at any time. The type chip appears on the list, detail, and ledger views and can be filtered on the index.
  - **Full series editing in the UI.** Edit a series' name, cadence, expected amount, category, and tags from the detail page. Create new series manually via `/recurring/new`.
  - **Interactive tag editing** on the series detail page — add or remove tags without leaving the page.
  - **"Price ↑" badge** appears in the ledger when a series' latest charge is higher than its expected amount.
  - **"Due in 30 days" stat tile** on the Recurring index, summing upcoming spend expected within the next 30 days.
  - **Series charges show a leading date column** in the ledger so you can scan payment history at a glance.
  - **`breadbox series reinfer-types`** re-runs type inference on all existing series. Run this once after upgrading if your instance was running before the type field shipped.
  - **New REST endpoints:** `PATCH /api/v1/series/{id}` (edit attributes and/or apply a verdict in one call), `POST /api/v1/series/{id}/type`, `POST /api/v1/series/{id}/tags`, `DELETE /api/v1/series/{id}/tags/{slug}`, `POST /api/v1/series/{id}/transactions`, `DELETE /api/v1/series/{id}/transactions/{txid}`.
  - **New MCP tools:** `update_series` (edit name, cadence, amount, category, and more), `set_series_type`, `add_series_tag`, `remove_series_tag`, `unlink_series_transactions`.
  {/* closes #1617, #1619, #1622, #1623, #1625, #1627, #1629, #1631, #1659, #1662, #1671 */}
</Update>

<Update label="May 30, 2026" description="Recurring-series MCP expansion: explain, rekey, split, and retroactive rule apply" tags={["MCP", "API"]}>
  - **`explain_series_candidates`** (`GET /api/v1/series/explain`) returns every recurring-looking merchant group that didn't qualify as a series, with the detector's near-miss verdict — useful for diagnosing why a charge isn't being tracked automatically.
  - **`rekey_series`** (`POST /api/v1/series/{id}/rekey`) corrects a series' `merchant_key` when auto-detection used a fallback key (e.g. `payment` instead of `netflix`). Linked charges are repointed to match.
  - **`split_series`** (`POST /api/v1/series/{id}/split`) moves a subset of a series' charges into a new series under a different `merchant_key` — for separating charges that were bucketed together incorrectly.
  - **Renewal-health and conditions** are now visible on the series detail page, showing the detector's confidence score and the criteria that qualified the series.
  - **`assign_series` rule action now applies retroactively.** When a rule fires, Breadbox also links all existing matching charges to the series, not just future ones.
  {/* closes #1609, #1613 */}
</Update>

<Update label="April 25, 2026" description="MCP annotations: kinds filter and generic event shape" tags={["MCP", "API"]}>
  - `list_annotations` now accepts an optional `kinds` filter using generic, agent-friendly names: `comment`, `rule`, `tag`, `category`. Empty (default) preserves the full-timeline behavior.
  - Each response row now carries the generic `kind` plus a separate `action` field (`added` / `removed` for `tag`, `set` for `category`, `applied` for `rule`) so agents can branch on the specific event without parsing the kind string. `kinds=['tag']` returns both add and remove events in one call.
  - The DB-level kinds (`tag_added`, `tag_removed`, `rule_applied`, `category_set`) are no longer accepted at the MCP boundary — pass the generic names instead. Internal admin views are unchanged.
  - `list_transaction_comments` is **deprecated** in favor of `list_annotations` with `kinds=['comment']`. The legacy tool still works but will be removed in a future release; note the field renames (`author_*` → `actor_*`, `content` → `payload.content`) when migrating.
  {/* closes #776 */}
</Update>

<Update label="April 24, 2026" description="One-liner installer and cross-platform daemon registration" tags={["Install"]}>
  - Breadbox can now be installed with a single command: `curl -fsSL https://breadbox.sh/install.sh | bash`. The installer auto-detects your OS, arch, package manager, and init system.
  - On Linux, the installer offers to register a systemd unit so Breadbox starts on boot. On macOS, it registers a launchd agent. Pass `--register-daemon` to accept without prompting.
  - Caddy (HTTPS reverse proxy) is now opt-in behind a Docker Compose profile. Localhost-only installs no longer bind ports 80/443. The installer prompts for an optional public domain and wires Caddy automatically when one is provided.
  - `update.sh` now preserves your installed version pin and only upgrades when you explicitly pass `--bump=vX.Y.Z` or `--bump=latest`.
  {/* closes #695, #694, #693 */}
</Update>
